做一个多人实时协作白板，浏览器里若干人同时在同一张画布上拖动图形、拉连接线、写便签，彼此看到的画面要实时一致。每个图元有位置、尺寸、层级与所属画布；连接线两端各锚在一个图元上，图元被移动或缩放时，连线的走向要跟着重新计算，不能还停在旧坐标上。前端要能看到其他协作者的光标位置与选中框，谁在动哪个元素一目了然。范围就是这张协作画布本身与其上的图元、连线、便签，经浏览器交互并由后端做实时广播与持久化，不涉及账户注册与付费。

画布有成员，成员有角色：可编辑与只读。角色由房主在协作过程中随时切换。关键点在于降级的时机：当一个正在拖动某图元的协作者被降级为只读，他手上这次未提交的移动要立即中断并回滚到降级前的位置，不能等他松手才生效，也不能把这半截脏位置广播给别人。只读成员的任何写操作一律拒绝并给出可读的原因，画面回到服务端的权威状态。

并发编辑要收敛：两个人同时改同一个图元的不同属性（一个挪位置、一个改颜色），两个改动都要保留，不能后到的把先到的整体覆盖；两个人同时改同一属性时，按服务端接收顺序定序，晚到者基于新基线重放，最终所有客户端看到同一份画布。掉线的协作者重连后，要能拿到当前完整快照并追上断线期间发生的增量，不能只靠本地缓存拼出一个与他人不一致的画面。

撤销与重做按人隔离：每个协作者只能撤销自己刚才做的操作，不能把别人的改动也一并撤掉；某人撤销自己三步之前移动某图元，而这期间别人又改过该图元的其它属性，撤销只回退该用户那一步涉及的部分，别人的改动保留。重做同理。撤销栈随会话维护，重连后能否续接由服务端的操作日志决定。

连接线的重算要正确：图元移动后，连线端点贴合到图元边界上离对端最近的锚点，路径避免穿过图元本体；两个图元靠得很近或重叠时仍给出确定的、可复现的走向，不能每次刷新抖动。删除某个图元时，挂在它上面的连线要一并处理而不是留下悬空端点。

启动后浏览器打开即是一块可多人协作的画布：开两个窗口，一个拖图元另一个能实时看到；把一方降级为只读，其进行中的拖动立即回弹且后续编辑被拒；各自的撤销互不牵连；连线随图元移动重算贴合。非法操作（越权写、连线锚到不存在的图元、坐标越界）要被拒绝并说明原因，不能让画布进入不一致状态。

前端用 React 与 TypeScript，画布交互与协作者光标在浏览器内实时渲染；后端用 Node.js 20 提供 HTTP 与 WebSocket，负责定序、广播、快照与增量、操作日志和权限判定；画布与图元、连线、操作日志持久化到 PostgreSQL 16，重启后画布内容与协作状态可恢复。代码请合理拆分为多个模块/文件：前端画布组件、协作者状态层，后端的连接与广播、定序合并引擎、连线路由、权限与角色、快照与增量、持久化各自独立成模块或文件，不要把定序合并和连线重算都堆进一个大文件。用 Docker Compose 一条命令把前端、后端与数据库一起拉起，对外暴露页面与接口。附自动化测试锁住：降级时进行中的拖动立即回滚且不广播脏位置、只读写操作被拒、同图元不同属性的并发改动都保留、同属性并发按接收顺序定序收敛、断线重连能取快照并追增量、撤销只回退本人操作且不影响他人对同图元的其它改动、图元移动后连线端点贴合最近锚点且路径可复现、删除图元时连线不留悬空端点、锚到不存在图元被拒。
